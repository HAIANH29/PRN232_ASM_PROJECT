# Physical Database

PostgreSQL is used with database-per-stateful-service ownership.

## IdentityDb

- `Users`
  - `Id`
  - `Email`
  - `NormalizedEmail`
  - `DisplayName`
  - `PasswordHash`
  - `IsActive`
  - `CreatedAtUtc`
- `Roles`
  - `Id`
  - `Name`
  - `NormalizedName`
- `UserRoles` join table generated by EF Core

Owned by `Identity Service`.

Initial migration exists: `InitialIdentitySchema`.

## DietKnowledgeDb

- `DietGuidelines`
- `Foods`
- `Recipes`
- `RecipeIngredients`

Owned by `Diet Knowledge Service`.

## MealPlanningDb

- `MealPlans`
- `MealPlanItems`

Owned by `Meal Planning Service`.

`UserId`, `RecipeId`, and `FoodId` are cross-service identifiers only.

## TrackingDb

- `DailyTrackings`
- `MealTrackings`
- `ProgressSummaries`

Owned by `Tracking Service`.

`MealPlanItemId` is a cross-service identifier only.

## Stateless Services

- `Recommendation Service` has no database in Phase 1.
- `Notification Service` has no database in Phase 1.
- `Notification Worker` has no database in Phase 1.

## Rules

- No service reads another service database directly.
- No cross-database foreign keys.
- Do not create `RecommendationDb` or `NotificationDb` unless a future persistence requirement needs them.
- EF Core migrations should be created per remaining stateful service in later implementation phases.
